# 五分钟课堂演示草案

以下流程在第四阶段已具备功能。第五阶段继续准备Mac桌面包与连续三次彩排；当前从本机网页启动。天气、地点和路线通过真实MCP调用，保留数据时间与来源。

| 时间 | 操作 | 讲解重点 |
| --- | --- | --- |
| 0:00–0:40 | 打开旅游宝，输入上海出发、两人、杭州三天、总预算 3000 元、美食偏好和少走路 | 产品场景、需求收集、Prompt 约束 |
| 0:40–1:40 | 选择接口预报范围内的旅行日期，生成行程；展开执行面板 | DeepSeek、工具调用、MCP 和 ReAct |
| 1:40–2:30 | 查看每日活动、预算和一处知识引用 | RAG 检索、来源与确定性预算计算 |
| 2:30–3:20 | 继续输入“第二天想以室内活动为主，其他条件不变” | Advisor 会话记忆与动态调整 |
| 3:20–4:00 | 保存行程、打开已保存列表、导出 Markdown | 应用业务与持久化 |
| 4:00–5:00 | 展示架构图及关键目录，解释工具失败时的处理 | 六项技术的边界与本机部署 |

## 演示前检查

- 本机启动脚本、模型、Embedding、MCP 与旅游提供方连接正常。
- 示例资料已入库，来源与核实日期完整。
- 使用新会话，明确预算是否包含城际交通和住宿。
- 天气以真实工具返回为准，不预设“当天一定下雨”。如演示条件分支，可明确输入“假设第二天下雨”，并标注为假设。
- 演示备用录像和截图标注录制日期、数据模式，不冒充当前实时结果。

## 可用于答辩的追问

- 只有 Prompt 时，系统从哪里获得可信旅游资料？
- Advisor 怎样把前一轮条件带入本次请求？
- RAG 的引用能否定位到实际检索片段？
- 本地 Tools、MCP 和 ReAct 分别解决什么问题？
- 工具不可用或智能体达到执行上限时，系统怎样结束？

## 第三阶段可立即演示的三分钟片段

1. 打开旅行知识库，说明六份资料来自杭州、苏州、上海的官方网页摘要，查看核对日期和原文。
2. 选杭州，检索“中国茶叶博物馆两个馆区的地址分别是什么？”，展示命中的原文片段。
3. 点击“让助手依据资料回答”，发送问题，展开引用：片段 ID、摘录、核对日与官方链接。解释 BGE-M3 负责找资料，DeepSeek 负责组织答案，Advisor 将本次资料加入上下文。
4. 再问“现在西湖游船还有多少张余票？”，展示资料不足，说明静态资料与实时工具的边界。
5. 打开已保存的上海博物馆行程，展示来源如何进入规划和 Markdown 导出；费用、步行和交通仍标明为估计。

## 第四阶段三分钟演示

1. 开始新会话，保持智能体开关，选明天杭州一日游、上海出发、2人、2000元，偏好茶叶博物馆两馆区、打车、全天步行不超过60分钟。
2. 提交后展开执行面板，说明“模型选择工具，MCP负责连接独立服务，真实结果再返回模型”。展示知识、天气、地点、路线、预算五类记录；校验错误如果被纠正，可用来解释反馈循环。
3. 查看最终步行合计、预算、知识片段与待确认事项。说明费用和步行为估计，天气是网格预报，道路耗时不包含实时路况。
4. 选择智能调整：“第一天少走路，步行降低到40分钟以内，多打车，其他条件不变。”对比日程合计，再保存与导出。
5. 展示停止按钮，说明6轮/10工具/90秒的边界，以及未校验成功的结果不会覆盖原有效行程。

2026-10-24实测示例：新规划5轮、7次工具，模型纠正步行及JSON错误后完成，步行58分钟；另一条网页智能调整3轮、5次工具，从48分钟降至38分钟。模型输出有波动，课堂不要求重复得到相同数字。截图是历史实测结果，不能代替演示当天的查询。
