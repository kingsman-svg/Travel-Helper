适用范围：第一至第四阶段，2026-10-24。下面是供你独立执行的操作步骤；已有验收记录不能替代你本次运行的结果。真实模型内容可能不同，核对日期、人数、约束和计算关系，不要求输出与截图逐字一致。

## 1. 构建并启动

在 Mac“终端”打开第一个窗口，依次运行：


## 2. 验证连接页

左侧选择“连接状态”，逐个点击“验证连接”，等待当前项目结束后再点下一个。这些验证会真实访问相关服务；模型验证会产生少量 API 用量。

| 勾选 | 项目 | 通过标准 |
| --- | --- | --- |

## 3. 生成并调整行程

验证普通规划时，点击“开始新的对话”，取消勾选“智能体规划”，填写一组固定需求：

| 字段 | 测试输入 |
| --- | --- |
| 出发地 / 目的地 | 上海 / 杭州 |
| 日期 | 2026-11-01 至 2026-11-03；也可选其他连续三天 |
| 同行人数 | 2 |
| 总预算 | 3000 元 |
| 预算包含项 | 五项全部勾选 |
| 偏好 | 喜欢美食和湖景。第一、三天正常游玩，第二天先安排约60分钟步行，后续再调整。 |

- [ ] 点击“生成我的行程”，先显示处理状态，随后出现连续三天的卡片，目的地、人数与日期正确。
- [ ] 展开每天卡片，活动有开始/结束时间、地点、交通、估计步行与费用说明。
- [ ] 预算面板显示分类合计、总预算和余额；“本次行程检查”有 `check_schedule` 与 `calculate_budget`，触发方式标为“后端校验”。耗时 0ms 表示不足一毫秒，不代表未执行。
- [ ] 记下第一、三天的安排和第二天的步行总量。

在下方选择“调整行程”，发送：

> 第二天少走路，请把第二天估计步行总量降低到30分钟以内，多休息；第一、三天不变。

- [ ] 第二天步行总量降低，且不超过 30 分钟。
- [ ] 第一、三天活动保持一致，目的地、人数、日期和预算口径不变。
- [ ] 行程版本增加，显示待保存草稿，预算随实际费用重新计算。

如果原来的第二天已经很少走路，可以改成更小且可行的上限。若模型两次输出仍不合格，应出现明确失败提示，原有效行程保留；这表示拦截机制有效，但该次生成/调整不能记为成功。

模型可能给出超预算方案，界面应显示超出金额。估计费用不能当作实时票价，预算准确指合计正确，不代表每份方案都会自动满足预算。

## 4. 手动编辑与预算计算

- [ ] 点击“编辑安排与费用”，修改标题或活动名称，点击“应用编辑并校验”；标题/活动更新，版本增加。
- [ ] 选择一笔已包含在预算内的费用，例如把 80 元改为 80.30 元。应用后，预算包含项合计应增加 0.30 元，余额减少 0.30 元。
- [ ] 手动相加“住宿 + 餐饮 + 交通 + 门票 + 其他”，应等于“全部费用估算”。五项全选时，也等于预算包含项合计。
- [ ] 验证预算口径：重新填写需求，取消勾选住宿并重新生成。此时预算包含项合计应等于其余四类之和，住宿仍属于预算外估算。不要用重新生成前的总额直接比较，因为模型可能同时调整其他费用。

## 5. 无效输入与原行程保护

| 勾选 | 操作 | 应看到的结果 |
| --- | --- | --- |
| [ ] | 人数填 0、预算填 0，或必填城市留空 | 表单不能提交，出现校验提示 |
| [ ] | 结束日期早于出发日期，或旅行超过 14 天 | 不能生成有效行程，提示日期问题 |
| [ ] | 取消全部预算包含项 | 提示至少选择一项 |
| [ ] | 在编辑中把某活动结束时间设为早于开始时间，再应用 | 提示时间错误；原有效草稿的版本与预算不变 |
| [ ] | 在编辑中让两个活动时间重叠，再应用 | 提示重叠；原有效草稿保留 |
| [ ] | 费用填负数 | 浏览器或后端拒绝，不产生有效的新版本 |

编辑失败后可以点击“取消编辑”回到原有效行程。缺失密钥、认证错误消息脱敏、非法 JSON 和旧版本覆盖保护也有代码/接口测试，不必修改现有密钥来验证。

## 6. 保存、草稿与导出

- [ ] 保存有效行程，记下保存版本、标题与预算。
- [ ] 进入“已保存行程”，能看到它；点击“打开行程”能继续查看和调整。
- [ ] 点击“导出已保存版本”或列表中的“导出 Markdown”，下载 `.md` 文件；用文本编辑器打开，核对日期、人数、活动、费用和待确认项。
- [ ] 修改并应用一个标题，但先不点击“保存行程”。页面应显示待保存草稿；此时导出的文件仍是上次明确保存的标题与内容。
- [ ] 再点击“保存行程”，重新导出，文件应包含新标题与新版本；保存列表更新原条目。

“打开行程”恢复该会话的最新草稿，因此可能包含尚未明确保存的修改；它不执行“撤销草稿”。导出始终以明确保存的快照为准。



## 11. MCP 与 ReAct 智能规划

1. 开始新会话，保持“智能体规划”勾选。输入上海出发、杭州、2人、总预算2000元、全部预算项；日期选明天往返（公开天气支持今天至未来15天）。
2. 偏好输入：“中国茶叶博物馆双峰馆区和龙井馆区一日游，根据天气安排。地点搜索用中国茶叶博物馆，选择两个museum类地点查询路线。优先打车，全天步行不超过60分钟，费用为两人总估计。”
3. 点击生成，展开“ReAct · 真实工具执行”。应看到实际 `search_knowledge`、`weather_forecast`、`search_places`、`plan_route`、`calculate_budget` 记录，顺序与次数由模型选择。点击“查看参数与实际结果”可核对原始JSON。
4. 天气含日期、温度、降水概率、提供方、查询及数据获取时间；地点含类别/地址/OSM来源；路线含公里、分钟、模式、渡轮提示与地图链接。它们是预报与估计，不等于现场实况或实时路况。命中知识与行程最终引用分别展示。
5. 执行最多6轮/10工具/90秒。中途校验错误可由模型在限制内纠正；完成后，日程实际步行合计应不超过60分钟，并且版本增加。失败应显示明确终止状态，不能把这一轮记为成功。
6. 选择“智能调整”，输入“第一天少走路，请把第一天估计步行总量降低到40分钟以内，多利用出租车，其他条件不变，重新核对天气与路线。”应产生新一轮真实工具记录；新行程的当天步行小于之前且不超过40分钟，城市、日期、人数和预算口径不变。
7. 保存后重新打开，仍能展开对应成功执行记录。Markdown保留知识文档/片段ID与智能体执行ID；后续手动编辑可能改变行程，执行记录保存的是当时结果。
8. 再发起智能调整，执行中点击“停止智能规划”。应结束等待、显示已停止，草稿版本与原有效行程保持。刷新后原成功草稿仍关联其成功记录；最近取消记录可从API查询。

公开服务不可用、日期超范围或城市未覆盖时，应看到明确状态及待确认事项。不要把模型仍能生成文字方案误当成该接口已经查询成功。课堂建议使用杭州、苏州、上海；其他城市可取消智能体开关，使用普通规划。

```bash
node /Users/secondlaw/docker-ssh-workspace/travel/scripts/verify-day4.mjs
# 停止服务并重新启动后
node /Users/secondlaw/docker-ssh-workspace/travel/scripts/verify-day4.mjs --after-restart
```

脚本创建独立验收会话，发起真实API请求，会产生少量DeepSeek用量。第一段验证七组：工具发现、天气字段、超范围/城市状态、地点/路线、完整ReAct、保存/导出、取消保护。第二段检查重启后执行事件与行程摘要完全一致。只有全部通过，`.data/verification/day4.json` 的 `allPassed` 才为 true。网页人工验收记录在 `.data/verification/day4-ui.json`。
