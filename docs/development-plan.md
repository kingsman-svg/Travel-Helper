# 旅游宝五天开发计划

原计划周期：2026 年 10 月 22 日至 26 日，时区 Asia/Shanghai。第一、二、三、四天内容均已完成；第二阶段按用户要求于 10 月 22 日提前开发，第三阶段于 10 月 23 日提前完成，第四阶段于10月24日提前完成，后续日期保留为原排期。详见 [第一天记录](day1-report.md) 、[第二天记录](day2-report.md) 、[第三天记录](day3-report.md) 与 [第四天记录](day4-report.md)。预计每天投入约 4–6 小时。

## 首版交付约定

用户可以输入旅行需求，得到可编辑的每日行程；继续对话修改行程；保存并导出计划；查看旅游知识引用、预算结果和真实工具执行记录。

示例知识库覆盖杭州、苏州、上海。首版使用本机单用户模式、H2 文件数据库和本地向量存储。大语言模型使用 DeepSeek API，Embedding 独立配置，首选 Ollama + BGE-M3。

五天内暂缓账号权限、支付预订、实时酒店库存、多人协作、移动端 App、全国数据采集和完整交互地图。路线优先展示摘要与地图跳转链接。

## 第 1 天：环境和最小调用链

- [x] 创建 Java 应用入口、健康接口和本机启动/停止脚本；启动时统一工作目录并加载 `.env`。
- [x] 使用本机填写的 DeepSeek 密钥完成真实文本调用，模型名可配置。

验收：一条真实回答在页面出现；DeepSeek 工具调用、MCP 协议调用、Embedding 分别记录一次成功结果。缺失密钥或依赖时展示具体缺项，不能记作验证通过。

依赖准备：用户在本机配置 DeepSeek API Key；第四阶段采用无需密钥的公开天气与地图服务；密钥不写入文档和前端。优先在第 1 天暴露网络、模型接口和 SDK 兼容性问题。

## 第 3 天：RAG

- [x] 每个示例城市整理至少两份资料，记录标题、来源链接、适用城市、核实日期和文档 ID。
- [x] 首版只接收 UTF-8 Markdown / TXT；上传限制、解析错误和索引状态有明确提示。
- [x] 实现文档分块、Embedding、索引写入、按城市过滤和相关片段检索。
- [x] 使用 RAG Advisor 将资料加入模型上下文；会话记忆与检索配置能共同生效。
- [x] 检索片段携带来源；回答中的引用能对应到实际命中的原文。
- [x] 通过 H2 事务持久化文档、向量与索引元数据；修改 Embedding 模型或维度时要求重建索引。
- [x] 完成知识库页面、上传状态、资料列表、来源展示。

验收：准备十条有人工参考答案的资料问答，至少八条正确引用支持其回答的资料；检索不到答案的样例明确说明资料不足。重启后可检索，重复导入相同资料不会产生重复引用。

## 第 4 天：MCP 与 ReAct

- [x] MCP 服务实现 `weather_forecast`、`search_places`、`plan_route`，对接实际提供方。
- [x] 工具定义包含参数说明和输入校验；结果包含提供方、查询时间和可用状态。
- [x] 天气日期超出接口预报范围、地点不存在或提供方失败时返回明确结果。
- [x] 主后端通过 MCP Client 注册外部工具，与本地工具统一供智能体选择。
- [x] 使用一个受控的模型—工具执行循环，避免手写循环与框架自动工具循环重复驱动。
- [x] 形成“选择工具 → 执行 → 接收结果 → 更新计划 → 完成”的 ReAct 流程。
- [x] 初始限制：最多六轮模型决策，累计工具调用最多十次，总时间九十秒；支持取消和错误终止。
- [x] 流式发送行动摘要、知识引用、工具开始/结束、最终行程和终止事件。
- [x] 前端执行面板展示真实工具名、参数摘要、结果和耗时。

验收：一条规划任务实际使用知识资料、MCP 工具和预算工具，最终给出有来源的行程。工具失败、达到轮数上限、取消请求三种情况都能终止，界面不会一直等待。

## 依赖顺序与调整规则

```text
真实模型调用与协议验证
  → 结构化行程、存储、会话与本地工具
  → RAG 与来源
  → MCP 真实数据与 ReAct
  → 联调、交付和彩排
```

每日完成后记录实际验证结果；未通过的关键依赖优先于页面美化。落后时先减少视觉装饰和额外城市资料，保留六项技术的真实最小链路。外部接口不可用时明确显示未配置或不可用；固定样例仅用于标明模式的演示，不替代真实接入验收。

## 完成标准

能在当前 Mac 上按文档启动；用户完成一次真实的规划—调整—保存—导出流程；六项技术均能指向实际代码和演示证据；旅游资料可追溯；调用失败能够结束；关键构建与测试通过。
